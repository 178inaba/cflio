# CLAUDE.md

## Agent contract

atlio's primary consumer is an AI coding agent calling it from a shell; the conventions below exist to keep that contract stable.

- **Three-way documentation sync** — user-facing CLI behaviour is stated in `README.md`, the skill's files under `skills/atlio/` (`SKILL.md` and `references/*.md`), and the cobra help strings under `internal/cmd/`. Changing the CLI means updating all three in the same PR. Overlaps today, each stated in more than one of the three: the 90 s default `--timeout`; the exit codes; the default `md` output format; the read → edit → update cycle and the sidecar's version lock; `confluence update --title`'s renaming the page in the same request and the sidecar's refresh from the update response; the default filenames the two read modes write, and `--markdown`'s output being read-only; the `Degraded` and `Unchecked` counts `confluence read --markdown` reports; `confluence read --attachments`'s requiring `--markdown`, and its keeping a file already at the destination rather than replacing or re-fetching it; `confluence attachments download`'s and `jira attachments download`'s required `--pattern` and their refusal to overwrite an existing file, and both commands' refusal, before any transfer, of matched attachments that would be written to one file, names compared ignoring case and Unicode normalisation, and `jira attachments download`'s writing matched attachments whose filenames are equal by that comparison each under a name carrying its attachment ID; `confluence plantuml`'s read → `get` → edit → `set` → `confluence update` flow, `set`'s bumping `revision` and why the viewer needs it, `set`'s refusing a macro with no `ac:local-id` on a live doc, `add`'s generating both identifiers and why `ac:local-id` cannot be left to Confluence, `add`'s `--after` anchor and its appending at the end of the body without one, and `add`'s default `filename`; `confluence comments create`'s sending the file's bytes as the `storage` representation unconverted, its `-f -` stdin form, and its posting top-level footer comments only; `confluence create`'s required `--parent`, its sending the file's bytes as the `storage` representation unconverted, its writing the sidecar so `confluence update` needs no read, and its refusal of a file that already has a sidecar; `confluence attachments upload`'s leaving the body untouched and the upload → read → add `<ac:image>` → `confluence update` flow that shows the file, its refusing a name the page already has an attachment under unless `--replace`, which uploads a new version, and the page's showing that new version without a `confluence update`; `confluence attachments upload`'s accepting regular files only; the creating commands' (`confluence create`, `confluence comments create`, `confluence attachments upload`) errors' saying when the request may have been carried out — after the whole request was sent, on a deadline, a `5xx` or an unparseable `2xx`, never on a `3xx` or `4xx` — and the check each names to make before re-running it, which `confluence update` does not need; short links being decoded locally and a blog post's decoding into a 404; a space's overview or space URL being accepted as a page reference for its homepage, and its costing one lookup unless it carries `homepageId`; `jira issue read`'s two modes, the default filenames they write (`<KEY>.adf.json`, `<KEY>.md`) and the `Degraded` count `--markdown` reports; the `Degraded` count `jira comments list` reports once for the listing; `jira search`'s passing the JQL to Jira as typed, and Jira's rejecting a query with no search restriction; issue keys and issue URLs as selectors; `auth login`'s saving the profile when either Confluence or Jira accepts the credentials; profile resolution; and `--version`'s printing the version the binary was built as.
- **The plugin description is a synced surface** — the one-line description in `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` (top level and the `plugins[]` entry) and the `homebrew_casks` entry in `.goreleaser.yaml` must be byte-identical, and must say the same thing as the repository's GitHub "About" text, the README's opening line, and `main.go`'s package comment, which pkg.go.dev renders as the module's description. Clients resolve two of these copies at different refs — the marketplace catalog from the default branch, the plugin manifest from `stable` — so they legitimately differ between a description edit landing on main and the next release; edit all four together and the release converges them.
- **Output format and exit codes are a contract** — `--format md|json` and the exit codes produced by `Execute` and `describeFailure` in `internal/cmd/root.go` (`0`, `124` when the `--timeout` deadline expires, following the GNU `timeout` convention, `1` for everything else) are branched on mechanically by agent consumers. An interrupt produces no code of atlio's own on Unix: atlio prints nothing and terminates by the signal, so a parent sees `WIFSIGNALED` rather than a normal exit. Changing any of them is a breaking change, held to a higher bar than for a human-facing CLI.
- **`stable` is moved only by the release workflow** — the `plugins[]` entry in `.claude-plugin/marketplace.json` resolves through the `stable` tag, the README's `npx skills` install command names it in the URL form, and `.github/workflows/release.yml` force-pushes it onto the new tag once the archives are published and attested. Moving it by hand ships content without changing the `version` in the manifest, and Claude Code keeps the copy it has cached, so updates stop silently. The exception is a release that got as far as attesting the archives and then failed on that last push: re-running the job moves nothing, since tagpr emits no tag once one exists, and the tagged tree already carries the bumped `version` — force-pushing `stable` onto that release's tag by hand is the repair.
- **The plugin's `version` lives in `.claude-plugin/plugin.json` only** — never on the `marketplace.json` entry. Claude Code always takes the manifest's value without warning, so a version in both places lets a stale manifest mask the other one. Keeping it in the manifest also puts it inside the tree `stable` points at, so the version a plugin advertises and the content it serves cannot disagree. tagpr bumps it through `versionFile` in `.tagpr`.
- **The skill is router-style** — activation conditions and workflow only; per-command syntax stays delegated to `atlio --help`, in `SKILL.md` and in each reference file alike. A statement that is true of every command, or that holds for both products, goes in `SKILL.md`, worded without either product's command prefix or object names (the routing entries, one per product, are the exception); a statement that holds for one product only goes in that product's `references/confluence.md` or `references/jira.md`. What a statement states decides, not what it names: a sentence that names one product's command but states a rule both products follow goes in `SKILL.md`. Each statement appears in one file of the skill only, and a reference file links to no other file of the skill.

## Code conventions

Shared across the sibling CLIs (atlio, rdsh, slio):

- cobra commands are wired constructor-style (`newXCmd()` returning `*cobra.Command`); no package-level command or flag variables.
- Output formatting lives in `internal/format`. An API-client package is named after the service, and its main file after the package.

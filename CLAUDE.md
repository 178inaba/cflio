# CLAUDE.md

## Agent contract

cflio's primary consumer is an AI coding agent calling it from a shell; the conventions below exist to keep that contract stable.

- **Three-way documentation sync** — user-facing CLI behaviour is stated in `README.md`, `skills/cflio/SKILL.md`, and the cobra help strings under `internal/cmd/`. Changing the CLI means updating all three in the same PR. Overlaps today, each stated in more than one of the three: the 90 s default `--timeout`; the exit codes; the default `md` output format; the read → edit → update cycle and the sidecar's version lock; `update --title`'s renaming the page in the same request and the sidecar's refresh from the update response; the default filenames the two read modes write, and `--markdown`'s output being read-only; the `Degraded` and `Unchecked` counts `read --markdown` reports; `read --attachments`'s requiring `--markdown`, and its keeping a file already at the destination rather than replacing or re-fetching it; `attachments download`'s required `--pattern` and its refusal to overwrite an existing file; `plantuml`'s read → `get` → edit → `set` → `update` flow, `set`'s bumping `revision` and why the viewer needs it, `set`'s refusing a macro with no `ac:local-id` on a live doc, `add`'s generating both identifiers and why `ac:local-id` cannot be left to Confluence, `add`'s `--after` anchor and its appending at the end of the body without one, and `add`'s default `filename`; `comments create`'s sending the file's bytes as the `storage` representation unconverted, its `-f -` stdin form, and its posting top-level footer comments only; the retired `cflio comments <page>` form and the `cflio comments list` that replaced it; short links being decoded locally and a blog post's decoding into a 404; profile resolution; and `--version`'s printing the version the binary was built as.
- **The plugin description is a synced surface** — the one-line description in `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` (top level and the `plugins[]` entry) and the `homebrew_casks` entry in `.goreleaser.yaml` must be byte-identical, and must say the same thing as the repository's GitHub "About" text, the README's opening line, and `main.go`'s package comment, which pkg.go.dev renders as the module's description. Clients resolve two of these copies at different refs — the marketplace catalog from the default branch, the plugin manifest from `stable` — so they legitimately differ between a description edit landing on main and the next release; edit all four together and the release converges them.
- **Output format and exit codes are a contract** — `--format md|json` and the exit codes produced by `Execute` and `describeFailure` in `internal/cmd/root.go` (`0`, `124` when the `--timeout` deadline expires, following the GNU `timeout` convention, `1` for everything else) are branched on mechanically by agent consumers. An interrupt produces no code of cflio's own on Unix: cflio prints nothing and terminates by the signal, so a parent sees `WIFSIGNALED` rather than a normal exit. Changing any of them is a breaking change, held to a higher bar than for a human-facing CLI.
- **`stable` is moved only by the release workflow** — the `plugins[]` entry in `.claude-plugin/marketplace.json` resolves through the `stable` tag, and `.github/workflows/release.yml` force-pushes it onto the new tag once the archives are published and attested. Moving it by hand ships content without changing the `version` in the manifest, and Claude Code keeps the copy it has cached, so updates stop silently. The exception is a release that got as far as attesting the archives and then failed on that last push: re-running the job moves nothing, since tagpr emits no tag once one exists, and the tagged tree already carries the bumped `version` — force-pushing `stable` onto that release's tag by hand is the repair.
- **The plugin's `version` lives in `.claude-plugin/plugin.json` only** — never on the `marketplace.json` entry. Claude Code always takes the manifest's value without warning, so a version in both places lets a stale manifest mask the other one. Keeping it in the manifest also puts it inside the tree `stable` points at, so the version a plugin advertises and the content it serves cannot disagree. tagpr bumps it through `versionFile` in `.tagpr`.
- **`skills/cflio/SKILL.md` is router-style** — activation conditions and workflow only; per-command syntax stays delegated to `cflio --help`.

## Code conventions

Shared across the sibling CLIs (cflio, rdsh, slio):

- cobra commands are wired constructor-style (`newXCmd()` returning `*cobra.Command`); no package-level command or flag variables.
- Output formatting lives in `internal/format`. An API-client package is named after the service, and its main file after the package.
